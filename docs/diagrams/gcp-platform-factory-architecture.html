Platform Factory — GCP Reference Architecture

Four independently-applied Terraform layers, split by lifecycle, not resource type: identity and reachability persist across working sessions; compute is disposable and rebuilt on demand. Terraform's job ends the moment Argo CD is running and pointed at platform-config — everything above that line is GitOps.

the four layers
0-foundation persists · applied once

The substrate everything else assumes exists. Starts on local state, then migrates itself into the bucket it creates.

  • google_project under the thecloudgeek.io org, billing linked
  • 7 enabled APIs (compute, container, iam, …)
  • GCS state bucket <project>-tfstate, versioned
~$0 idle · never touched after first apply
1-network persists · reachability

Promoted to its own layer because a real corporate cloud never lives by itself — the VPN peer config must survive cluster rebuilds.

  • Custom-mode VPC · subnet 10.10.0.0/20
  • Secondary ranges: pods 10.20/16, services 10.30/20
  • HA VPN pair + Cloud Router, BGP — enable_vpn gated, off by default
$0 with VPN off · ~$36/mo once tunnels are live
2-cluster torn down · compute

The expensive part, configured corp-real (ADR-0009): regional control plane, private nodes. Reads network facts from 1-network's remote state by name — so it can die and be reborn without touching the VPC.

  • GKE regional us-central1 · private nodes + Cloud NAT
  • API endpoint locked to authorized networks · workload identity
  • Node pool: e2-standard-4 on-demand, shielded, 1–2 per zone
~$0.50/hr while up (regional fee + nodes) · destroyed at session end
3-argocd torn down · handoff

Terraform's last job: install the thing that replaces it. Authenticates with a short-lived token — no static credentials in state.

  • helm_release argo-cd 10.2.2 (Argo CD v3.4.6)
  • Root Application via extraObjects → platform-config
  • Auto-sync off until platform-config has real manifests
Free · rides on 2-cluster, dies with it

boundaries
Where Terraform stops. Once the root Application syncs, everything else — workloads, namespaces, Gateway routes, Kyverno policies, secrets wiring, DNS — is declared in platform-config and applied by Argo CD, never by terraform apply. That boundary is claim C-01 ("Terraform ends at layer 0") in the pre-registered build experiment, and the four-layer split is the shape of C-02 ("teardown/rebuild is cheap enough to run between sessions").
Irreducibly manual — the full list, named as evidence: two browser logins (gcloud auth login, gcloud auth application-default login), the free-trial signup, and one terraform init -migrate-state after the state bucket exists. Everything else is code.
